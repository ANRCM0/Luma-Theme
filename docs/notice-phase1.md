# vv-theme 公告系统 · 第一阶段（0.3.0）

本版本沿用 TXBoard **真实公告数据**，不新建公告表或业务 API。

## 运营人员如何使用

1. TXBoard 管理后台 **公告管理 → 添加 / 编辑公告**：填写标题、正文、可选图片和标签（逗号分隔）。
2. 勾选「前台显示」后，该公告会进入 vv-theme **公告中心**（顶部铃铛）。
3. 如果需要主动弹窗，另外勾选公告自身的「弹窗展示」开关。未勾选的普通公告不自动弹窗，但可在公告中心查看。
4. 在 **主题管理 → vv-theme → 设置** 中控制主题的自动弹窗总开关、匹配标签、提醒频率、弹出范围和样式。这些配置独立于 TXBoard 其他主题，不会覆盖系统外观。
5. 想仅让标签为「重要」的公告弹窗：先在公告中设置标签 `重要` 并勾选弹窗，再把 vv-theme 的「公告 · 自动弹窗标签」设为 `重要`。输入 `重要,活动` 表示匹配其中任一标签，留空表示不按标签限制。

**优先级：** TXBoard「前台显示」决定是否返回公告；公告「弹窗展示」决定是否能主动弹窗；vv-theme 的标签、频率及范围设置决定是否在本次访问中展示弹窗。这些条件需要同时成立。

## 可配置项

| 配置键 | 控件 | 默认 | 说明 |
| --- | --- | --- | --- |
| `notice_popup_enabled` | switch | 1 | 总开关；关闭后仍可用公告中心查看 |
| `notice_center_enabled` | switch | 1 | 顶部铃铛和公告中心显示；独立于弹窗 |
| `notice_popup_tag` | input | 空 | 逗号分隔，精确匹配公告 tags（不区分大小写）；空为全部 |
| `notice_popup_frequency` | select | once | `once` 每条公告版本只提醒一次；`session` 每条公告每浏览器会话一次；`daily` 每条公告每 24 小时一次；`always` 每次加载页面提醒 |
| `notice_popup_scope` | select | all | `all` 登录后任意页面；`dashboard` 仅用户主页 |
| `notice_popup_style` | select | classic | `classic` 经典；`compact` 简洁；`feature` 强调 |

后端通过 `GET /api/v1/guest/comm/config` → `theme_config` 下发公开配置。兼容旧版 TXBoard：如果接口未返回当前 vv-theme 的配置，则使用 Blade 注入的 `window.settings.notice`。

## 阅读状态与防打扰

- 已读是**每个账号、每个公告版本**独立记录；版本由 `id:updated_at` 组成。如果公告正文更新并改变 `updated_at`，该公告会被视为新版本。
- 本地仅存账号标识、公告版本、频率时间戳，不存公告正文或身份凭证。已读状态不跨设备同步。
- 浏览器禁用存储时，公告显示本身仍可用，但关闭后的持久防重可能失效。
- 单次页面加载最多自动弹窗一次。公告中心可从「全部／未读」浏览，并提供「全部标为已读」。
- 主题目前最多提取 5 页、500 条显示中的公告（每页 100 条）；大量公告的长期归档应另行提供分页查询。
- 公告正文按**文本**渲染，不执行管理端输入的 HTML/脚本；支持文字换行和附图。主题只有展示权限，不更改 TXBoard 的公告数据库。

## 验证与上线

主题包版本 `0.3.0`。安装后请验证：普通公告不弹、已勾选弹窗且标签匹配会弹、已读后刷新不再弹、新公告或公告更新重新提醒、深色模式和移动端，以及关闭通知中心开关的效果。

构建测试：

```sh
npm test
TXBOARD_THEME=true TXBOARD_THEME_PREVIEW=true npm run build
npm run test:live
```

真实站点测试需要通过 TXBoard 管理后台创建公告；仓库 CI 使用模拟 API 测试，不会修改线上公告。
