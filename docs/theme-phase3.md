# vv-theme 第三阶段 · 动态欢迎卡片（v0.5.0）

## 核心能力

本阶段只改主题表现，不改变 TXBoard 订阅、计费、权限和订单处理。前台读取登录用户的：

- `/api/v1/user/info`：`created_at`（注册时间）、`plan_id`、`transfer_enable`（用户流量额度，字节）、`balance`。
- `/api/v1/user/getSubscribe`：`plan_id`、`plan`、`expired_at`（Unix 秒）、`u`／`d`（已上传和下载，字节）、`transfer_enable`（总额度，字节）、`reset_day`。

仅使用这些已有字段进行状态展示；不会向后端写入额外的用户标签。

## 用户状态判定

| 状态 | 识别规则 | 首页提示 / 操作 |
| --- | --- | --- |
| 新注册（`new`） | 没有套餐，且注册距今不超过默认 48 小时 | 欢迎引导、浏览入门套餐 |
| 无套餐（`no_plan`） | 没有套餐且不是新用户 | 引导购买套餐 |
| 已过期（`expired`） | 有套餐且有效期截止时间不晚于当前 | 续费套餐、历史订单 |
| 流量已用完（`exhausted`） | 有套餐、未过期、可确认剩余流量为 0 | 升级套餐、联系支持 |
| 即将到期（`expiring`） | 有套餐，剩余有效期不超过默认 72 小时 | 续费提醒 |
| 流量不足（`low_traffic`） | 当前剩余流量不超过 GB 与百分比阈值中的较小值 | 升级提示 |
| 正常（`normal`） | 其他有套餐的状态，包括永久套餐、流量额度未知 | 订阅概览 |

**判定优先顺序：** 有无套餐 → 已过期 → 流量已用完 → 即将到期 → 流量不足 → 正常；无套餐用户则优先识别新用户。

示例：总流量 5 GB，`welcome_low_traffic_gb=10` 且 `welcome_low_traffic_percent=10`，实际阈值是 **0.5 GB**（两者取较小值），避免小额度套餐刚开通就提示流量不足。额度或到期时间无法确认时不会凭空生成警告。

## 后台主题配置

打开 TXBoard「主题管理 → vv-theme → 设置 → 个性化欢迎」：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `welcome_enabled` | 1 | 开关，关掉后显示通用欢迎卡片 |
| `welcome_new_hours` | 48 | 新注册用户识别时长（小时） |
| `welcome_expiry_hours` | 72 | 到期前提醒（小时） |
| `welcome_low_traffic_gb` | 10 | 绝对流量阈值（GB） |
| `welcome_low_traffic_percent` | 10 | 剩余流量比例阈值（%） |
| `welcome_secondary_card` | recommend | 侧栏选项 `recommend` 推荐套餐、`usage` 流量概览、`wallet` 账户钱包 |

所有配置都属于当前主题；新 TXBoard 读取 `theme_config`，旧版通过 Blade 注入 `window.settings.welcome` 回退，不依赖全局外观页面。

## 数据与安全约束

- 到期时间为零或缺失时视为未指定有效期，不误判为过期。
- 不混淆字节与 GB：`getSubscribe.transfer_enable` 的单位是字节，`plan.transfer_enable` 是 GB。
- 主题仅按当前登录用户的 API 结果展示信息；优惠和价格计算仍由 TXBoard 后端裁决。
- 余额卡片不会向未登录访客公开账户余额。
- 已有购买、续费、工单链接不更改原来的 TXBoard 业务接口。
- 状态只在页面加载、用户数据更新时重新计算；若页面持续不刷新，到期提醒需要刷新后才能更新。

## 升级与回归

上传 **v0.5.0** ZIP，确认「个性化欢迎」分组和设置项出现。

自动测试包括状态优先级、七类场景、配置范围、数据缺失、字节/GB、时间戳单位、首次登录与续费入口、流量使用及手机宽度。真实环境应再用预发布账户核验无套餐、订阅到期、套餐额度为零及永久套餐等场景。原有的公告、购买、账务、侧边栏以及登录安全逻辑保持不变。
