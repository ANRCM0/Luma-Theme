# vv-theme 第四阶段：套餐商店与购买流程（v0.6.0）

## 实现范围

保留 TXBoard 原有的业务接口和交易逻辑，只升级用户侧展示：

1. 用户购买套餐页支持全部周期与独立月付、季付、半年付、年付、两年付、三年付、一次性筛选。每张卡片的价格与筛选周期一致，避免过去“点年付但卡片始终显示月付起”的歧义。
2. 管理员可指定精选套餐 ID，显示“精选套餐”标记。没有指定时不自行创造“最受欢迎”排名。
3. 每个套餐最多三款同时对比价格、流量、设备限制、速度和可选周期。手机端对比表横向滚动，不会挤占页面。
4. 月付与长周期同时有实际价格时，显示“对比连续按月购买 N 个月，可少付多少”。只在有真实正数差额时显示，不计算一次性套餐、流量重置价格或未配置价格。
5. 购买分为选择周期 → 优惠码（可选）→ 创建订单 → 查看后端实际金额并支付。修改周期或优惠码会清除旧校验结果，防止误用过期预览。
6. 所有套餐价、折扣、余额、手续费只做说明；**真实订单应付金额以 TXBoard 后端 `order/detail` 返回的 `total_amount` 为准**。不能依赖前端计算授权或收费。

## 真实数据和安全边界

- 套餐列表：`GET /api/v1/user/plan/fetch`。TXBoard `PlanResource` 返回 `month_price`、`year_price` 等字段，单位为**分**（人民币元乘以 100），`show`、`sell` 决定销售展示。后端 `PlanService` 再执行套餐可用性校验。
- 不把 `reset_price` 混作一般订阅周期：流量重置的购买有额外授权及在订阅有效期内的约束。
- 下单：`POST /api/v1/user/order/save`，使用 `plan_id`、TXBoard 兼容的周期键、可选 `coupon_code`。后台决定套餐销售状态及实际价格。
- 优惠码验证：`POST /api/v1/user/coupon/check`，验证结果仅是当前套餐／周期的状态。订单创建时服务端再次核验。
- 订单核对：`GET /api/v1/user/order/detail`，返回 `total_amount`、`status`、`period` 等，支付服务和已有 Stripe 安全组件保持不变。
- 当前如存在未支付订单，将先要求用户明确确认后取消旧订单；正在开通中的订单禁止创建新单。不会自动替用户取消订单。

## 后台主题设置

TXBoard → 主题管理 → vv-theme → 设置 → **套餐商店**：

| 字段 | 默认 | 用途 |
|---|---|---|
| `shop_default_period` | `all` | 商店初始筛选周期，全部或单独周期 |
| `shop_featured_ids` | 空 | 逗号分隔套餐 ID，例如 `1,3` |
| `shop_compare_enabled` | 1 | 启用最多三款套餐对比 |
| `shop_show_savings` | 1 | 显示有事实依据的周期价格差额 |
| `shop_show_description` | 1 | 显示服务端套餐说明（以文本呈现，不执行 HTML） |

升级后配置优先从公开当前主题的 `theme_config` 读取；旧版 TXBoard 可从 Blade `window.settings.catalog` 回退。与前三阶段设置互不覆盖。

## 验收和回滚

- 购买测试：月付 / 年付 / 一次性 / 免费价格（存在时）、无该周期时筛选结果、精选套餐、套餐对比。
- 订单测试：修改周期后优惠码校验清除；选择年付时下单提交 `year_price`；前端基础价与服务端订单实际应付分开展示。
- 浏览器测试：390px 手机无横向溢出；后台配置关闭对比与描述时按开关生效。
- 上线前务必在 TXBoard **预发环境**完整测试支付方式、优惠码使用限制、续费限制和异步支付回调。
- 如果要回滚，切回此前的 vv-theme ZIP 或 TXBoard 内置主题，后端订单数据不会被主题更换修改。
